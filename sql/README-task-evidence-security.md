## 0) نسخة احتياطية + تقرير القراءة فقط
1. لوحة Supabase → Database → Backups: تأكد من وجود نسخة حديثة (أو خذ نسخة يدوية).
2. SQL Editor → الصق `sql/precheck_readonly_report.sql` كاملًا → Run → انسخ عمود `report`.
3. الصق التقرير في الـ PR. التقرير لا يحوي أسماء أو بريدًا أو مسارات ملفات (المستودع عام).

**توقّف** إن كان:
- `stop` غير فارغ.
- `S7_storage_teacher_read_impact.WOULD_BE_CUT_old_match_but_not_new_key` أكبر من 0 (تُؤجَّل الخطوة 6 فقط).
- `S9_tasks_readiness.new_columns_already_present` غير فارغ (تطبيق جزئي سابق — راجعه أولًا).

## 1) تشديد الصلاحيات
`sql/phase_security_hardening_review.sql`:
- يسحب كل منح `anon` على جداول وتسلسلات ودوال `public`، والمنح الافتراضية المستقبلية.
- يعيد منح الدوال SECURITY DEFINER لـ `authenticated` و`service_role` فقط إن كانت لديهم قبل التطبيق.
- يمنع تعديل `profiles` مباشرة من العميل. الإدارة تتم عبر `admin-users` بـ service_role.

- **لماذا لا يكسر شيئًا:** الواجهة لا تقرأ أي جدول قبل تسجيل الدخول، ولا تعدّل `profiles` مباشرة (مُتحقَّق في `script.js`).
- **التحقق:** تفشل المعاملة كاملة إن لم تتحقق الشروط (`tx_check_*`).
- **الرجوع:** الكتلة المعلّقة في آخر الملف تعيد سياسة تعديل `profiles`. منح `anon` لا تُعاد لعدم وجود حاجة تشغيلية؛ إن احتجت دالة بعينها فامنحها صراحةً.

## 2) توسيع المهام (متوافق)
`sql/phase_task_schedule_evidence_review.sql`:
- يضيف `start_at` و`end_at` وأعمدة شاهد Drive. لا يوجد ربط للمهمة بحساب معلمة.
- قيود: النهاية بعد البداية، وتُملأ الأوقات معًا أو تُترك معًا، والرابط على نطاق Drive فقط.
- المشغّل يقصر تعديلات حساب المعلمات على رابط الشاهد واسمه، ويمنعه من مسح رابط موجود (يستطيع استبداله قبل الاعتماد)، ويجعل الاعتماد للقائدة فقط، ويقفل الشاهد المعتمد.
- سياستا RLS لحساب المعلمات المشترك: يرى كل مهام السنة النشطة مع «المسؤولة»، ويرفق الشاهد لأي مهمة منها لم يُعتمد شاهدها. لا إضافة ولا حذف.
- يحذف سياسات «مهامي فقط» (`tasks_select_assignee` و`tasks_update_assignee_evidence`) إن وُجدت من نسخة سابقة.

**الحساب المشترك:**
- جميع المعلمات يدخلن بالحساب نفسه، فلا يمكن معرفة المعلمة التي أرفقت الشاهد.
- «المسؤولة» معلومة تنظيمية للعرض فقط، وليست إثباتًا للهوية.
- `evidence_added_by` و`created_by` يحملان معرّف الحساب المشترك، دون نسبته إلى معلمة بعينها.

- **المهام القديمة:** تبقى أوقاتها NULL وأسماء المسؤولات كما هي، ولا تُجرى أي مطابقة تلقائية للأسماء.
- **الرجوع:** الأعمدة إضافية وغير ضارة للواجهة القديمة، والأفضل تركها. كتلة الحذف الكامل في آخر الملف تفقد ما أُدخل بعد التطبيق، فلا تُستخدم إلا عند الضرورة.

- **التحقق:** افتح `https://alalawirabab.github.io/platform/index.html` وأعد التحميل (Ctrl+F5)، ثم تأكد من ظهور حقلي «بداية المهمة» و«نهاية المهمة».
- **اختبار يدوي:**
  - الوكيلة: تضيف مهمة بأوقات و«المسؤولة» ورابط Drive.
  - حساب المعلمات: يرى المهمة واسم المسؤولة ويضغط «📎 إرفاق شاهد»، ولا يرى أزرار التعديل أو الحذف أو الاعتماد.
  - القائدة: تعتمد الشاهد.
- **الرجوع:** `git revert` لـ merge commit ثم push. الواجهة القديمة تعمل مع مخطط الخطوة 2.

## 5) حد محاولات الدخول (`username-login`)
الترتيب إلزامي: الدالة الجديدة ترفض كل دخول (503) إن لم يكن SQL مطبّقًا (fail-closed).

- **5أ.** `sql/phase_login_throttle_review.sql`.
- **5ب.** النشر:
  ```bash
  supabase functions deploy username-login --no-verify-jwt
  ```
- **5ج.** أسرار الإنتاج (مشتركة بين الدالتين):
  ```bash
  supabase secrets set ALLOWED_ORIGINS="https://alalawirabab.github.io"
  supabase secrets set PASSWORD_RESET_REDIRECT_URLS="https://alalawirabab.github.io/platform/index.html"
  ```
  وأزل `localhost` / `127.0.0.1` من Authentication → URL Configuration → Redirect URLs في الإنتاج.
  التطوير المحلي يكون عبر مشروع Supabase منفصل له أسراره الخاصة.

**السلوك:**
تُحتسب المحاولات الفاشلة فقط، خلال 15 دقيقة:

| العدّاد | الحد | الغرض |
|---|---|---|
| اسم المستخدم + الشبكة (IP) | 10 | القفل الأساسي. الدخول الناجح من الشبكة نفسها يمحوه |
| اسم المستخدم من كل الشبكات | 100 | سقف للتخمين الموزّع |
| الشبكة لكل الأسماء | 200 | سقف لتجربة أسماء كثيرة من مكان واحد |

عند تجاوز أي حد: `429 too_many_attempts` مع `Retry-After`، وتعرض الواجهة عدد الدقائق.

**لماذا لا تُحجب المدرسة (حساب مشترك من شبكة واحدة):**
- أخطاء الكتابة المتفرقة لا تتراكم، لأن كل دخول ناجح من المدرسة يمحو عدّاد المدرسة. مُختبَر: 27 خطأ متفرقًا بين دخولات ناجحة لا تقفل الحساب.
- القفل يحتاج 11 خطأ متتاليًا دون أي دخول ناجح، ويقفل هذه الشبكة فقط. الحساب نفسه يعمل من شبكة أخرى، وحسابات القائدة والوكيلة من المدرسة لا تتأثر.
- مهاجم من شبكة أخرى لا يستطيع قفل المدرسة إلا بـ 100 محاولة من 10 شبكات أو أكثر، وأقصى أثر 15 دقيقة. هذا هو الخطر المتبقي المقبول.

- تُحتسب المحاولات على الأسماء غير الموجودة أيضًا، حتى لا يُكشف وجود الحساب.
- تُخزَّن المفاتيح SHA-256 في `private.login_attempts`، وهو غير مكشوف عبر REST ولا يستدعيه إلا `service_role`. لا تُخزَّن كلمات مرور ولا عناوين IP صريحة.
- فحص Origin يبقى قيدًا للمتصفح فقط وليس وسيلة حماية.

**الرجوع:**
1. أعد نشر النسخة السابقة من الدالة:
   ```bash
   git checkout 5444302 -- supabase/functions/username-login
   supabase functions deploy username-login --no-verify-jwt
   ```
2. بعدها فقط، إن أردت، نفّذ كتلة الرجوع في ملف SQL.

## 6) قراءة المعلمة لملفات Storage
`sql/phase_storage_teacher_read_review.sql` يُطبَّق فقط إذا كان `S7...WOULD_BE_CUT...` = 0. وحتى لو لم يُتحقق من ذلك، فبوابة داخل المعاملة تُجهضها.

- **ما يتغير:** كانت المعلمة تستطيع توقيع أي ملف في الـ bucket، ومنها ملفات السنوات المؤرشفة.
- **بعد التطبيق تفتح المعلمة:**
  - ملفات مجلدها.
  - ملفات الشواهد التي تراها في المنصة، بمطابقة المفتاح نفسه الذي توقّع به الواجهة، ويشمل ذلك الروابط القديمة والأسماء العربية المرمّزة.
- **لا شيء يصبح عامًا.**
- **إن ظهرت ملفات متأثرة (S7 > 0):** لا تُطبَّق الخطوة، ويُرسل عدد الحالات لنصلح `file_url` لتلك الشواهد إلى مسار الكائن الفعلي بترحيل منفصل قبل التطبيق.

**الرجوع:** كتلة معلّقة تعيد السياسة السابقة حرفيًا.
